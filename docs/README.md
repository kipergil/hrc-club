# hertsttl.org.uk — modernisation

Planning documents for rebuilding the Hertford & District Table Tennis League website on **Directus** (backend) and **Nuxt 4 / Vue 3** (frontend), designed for an audience that is mostly older adults.

Read in order:

| Document | What it covers |
|---|---|

| [01-prd.md](01-prd.md) | The PRD. Goals, users, the **static vs dynamic analysis** that drives the architecture, functional requirements, the older‑user design requirements, security and privacy, the technology stack and why, success metrics, risks, cost |

## The short version

**What's wrong today.** The site is Microsoft FrontPage output on Classic ASP, served over HTTP only — HTTPS presents an invalid certificate. Not one of its 90 pages carries a viewport tag, so none of them work on a phone. The navigation menu opens on mouse hover and cannot be opened at all by touch. Login, including admin login, is an email address with no password. Body text is Comic Sans at fixed point sizes with crimson-on-salmon table headers. Three navigation links 404, the feedback form has been switched off by spam, and one page tells visitors the deadline is 27 December 1899.

**What's right today, and stays.** The information architecture matches how players actually think. Captains already enter their own results. Rules are explained in plain English next to the data they affect. Every page has a "Back to Home" link. URLs are short and have been stable for years. And the honours records go back to 1970 — the single most valuable thing on the site.

**The architecture.** Three tiers. About 35% of pages are genuinely static and are built at deploy time. About 55% hold dynamic data that changes on an *event* — a result being confirmed — not continuously, so they are rendered statically and regenerated by webhook when that event fires. Only about 10% (result entry, tournament entry, admin) need a live authenticated API. Roughly 90% of page views end up as static HTML from a CDN with no database on the request path.

**The design constraint.** 20px base type in rem units, 7:1 contrast, 48px touch targets, no hover-dependent behaviour anywhere, plain-English labels, an on-page text-size control, tables that reflow to cards on a phone, and real print support. Every one of those is a direct response to a finding in the audit.
